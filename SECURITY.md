# Security Policy

## Purpose

This project is intended for authorized asset inventory and
defensive/security testing workflows.

## Reporting a Vulnerability

Please report suspected vulnerabilities privately.

- Open a private security advisory on GitHub, or
- Email: [security@local.invalid](mailto:security@local.invalid)

Do not post exploit details in public issues before a fix is available.
Include enough detail to reproduce the issue safely:

- Affected version/commit
- Reproduction steps
- Impact and severity
- Any proof-of-concept details that can be shared responsibly

## Scope

In scope:

- Vulnerabilities in this repository's source code
- Packaging or release-process issues that impact user security
- Sensitive data exposure caused by project code or documentation

Out of scope:

- Findings on systems you do not own or have permission to test
- Denial-of-service or spam against public infrastructure
- Social engineering, phishing, or physical attacks
- Issues that require unsafe or unauthorized testing practices

## Response Timeline

- Acknowledgment: within 3 business days
- Initial triage: within 7 business days
- Status updates: at least every 14 days until resolution

Complex issues may take longer, but we will keep reporters informed.

## Responsible Disclosure

Please keep reports private until maintainers confirm remediation and
coordinate disclosure timing.

By reporting, you agree to test only authorized targets and to avoid
harmful, disruptive, or privacy-invasive behavior.
